OpenWSP: Benchmarking Weight-Space Programming on Open Language Models

Pedro Moreira  ·  Leonida Lumburovska

Weight-space programming asks an LLM to edit a neural network's weights directly, as it would edit code. OpenWSP is a benchmark that measures how well agents do it: it gives them the raw weights of small open language models and, with no gradients, asks them to work out how a model was made, change one of its behaviours, or teach it a new skill.

Three kinds of tasks

Every task hands the agent the weights of a 360M–1.7B model in a sandboxed Python kernel. Some tasks also allow a small budget of forward passes. Scores run from 0 (baseline) to 100 (perfect).

Read

How was this model made?

Find which data it was fine-tuned on, how it was merged from other models, which layers were transplanted, or which of two twins is backdoored.

Edit

Change one behaviour

Remove a backdoor, raise math accuracy, or make one word predict another, while changing nothing else.

Skill

Teach it a skill

From SQL and tool calling to OpenSCAD and COBOL, scored on held-out prompts the agent never sees.

Before and after

Real edits from the benchmark runs. For example, GPT-6.1 Sol changed one tensor of SmolLM2-360M, 0.00026% of its weights, and its accuracy on held-out SQL questions rose from 34% to 96.7%. Pick an agent and a task to see the unedited model and that agent's edited model answer the same practice prompts. The score is measured on hidden held-out prompts.

FAQ

What is weight-space programming?
Weight-space programming (WSP) means changing what a neural network does by reading and editing its weights directly, as a programmer reads and edits code, instead of training it on data with gradients. Takehi et al. (2026) recently showed, as a proof of concept, that frontier LLMs can read and write neural-network weights this way.
What does OpenWSP measure?
How well an LLM agent programs weights. In each of OpenWSP's 152 tasks, the agent gets the weights of a small open language model (360M–1.7B parameters) in a sandboxed Python kernel and, without gradients, must work out how the model was made (read tasks), change one of its behaviours and nothing else (edit tasks), or make it better at a skill, scored on held-out prompts it never sees (skill tasks).
Which LLM is best at weight-space programming?
On OpenWSP's 0–100 improvement index, GPT-6.1 Sol scores highest, with 51.0, followed by Claude Opus 5.5 (37.6), Claude Sonnet 5.5 (33.7) and GPT-6.1 Terra (29.0). The best open-weights agent, Qwen3.8-27B with thinking, scores 7.5.
How is a task scored?
From 0 to 100: 0 is the baseline and 100 a perfect solution. For edit and skill tasks, the baseline is the unedited model; for read tasks, it is a guess made from the task statement alone, without the weights. An agent's improvement index is its mean score over the 168 scored task cells, with a 95% bootstrap confidence interval.
How does OpenWSP differ from other weight-space programming benchmarks?
Three concurrent benchmarks also measure weight-space programming: WeightBench, IWIBench and WSPBench. OpenWSP is the only one of the four that asks agents to work out how a pretrained open language model was made from its weights, such as which data it was fine-tuned on or how it was merged from other models, and it measures skill teaching across 76 skills, each scored on held-out prompts.
